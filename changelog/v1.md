# V1 Changelog

Scope: the v1 personal-assistant agent as shipped on `main` (commit `4e4f5a6`, PR #1).
Source of truth: `design.md` (v1 sections) cross-referenced with the code under
`src/`, `config/v1/`, `tests/`, and `main.py`.

This document aggregates every item flagged in `design.md` as added, removed,
merged, simplified, or deferred relative to the original spec — plus the
implementation decisions that go beyond what `design.md` prescribed.

---

## 1. Sections added to the original design

These components were missing from the original spec and were introduced during
v1. Both are wired into `main.py` and exercised by tests.

### 1.1 Configuration management (design §1)
- Single `Config(BaseSettings)` class in `src/config.py` validated at startup
  via `pydantic-settings`; fail-fast on missing required values
  (`memory_root`, `index_path`).
- Priority order (highest → lowest): init args → env vars → `.env` → 
  `config/v1/app.yaml` → field defaults. A custom `YamlSettingsSource` adapts
  a versioned YAML file into pydantic-settings.
- `config/v1/app.yaml` is version-controlled; `llm_api_key` is intentionally
  absent from YAML and must come from `.env`/env vars.
- Config is injected as constructor arguments throughout; no component reads
  `.env` directly (see `main.py` wiring).

### 1.2 LLM client abstraction (design §2)
- Abstract `LLMClient` in `src/client/base.py` with `completion()` and
  `function_call()`. Singleton per concrete subclass via `__new__`/`_instances`.
- Concrete implementations: `ClaudeClient` (`src/client/claude.py`),
  `OpenAIModelClient` (`src/client/open_ai_model.py`, the live default pointing
  at local vLLM), plus `OpenAIClient` (`src/client/openai.py`).
- Components never call provider SDKs directly — every LLM call goes through
  this layer.

## 2. Items removed from the design

### 2.1 Memory retrieval sub-agent (design §6b)
Removed. Retrieval is handled entirely by `src/query/` +
`MemoryManager.get_context_with_keys()`. A separate sub-agent was redundant.

## 3. Items merged in the design

### 3.1 Memorize sub-agent distinct from memorize tool (design §6c)
Merged. The memorize tool (§8a) is the atomic write operation. The memorize
sub-agent (§6a) is the multi-step verification wrapper around it.

**Implementation note:** in v1 only the Strands `@tool` closure at
`src/tools/memorize.py` is wired into the agent. The `MemorizeSubAgent`
class in `src/agents/memorize.py` is retained for the future
`PostTurnMemoryHook` auto-memory pattern but is **not active** — no call
site invokes it today (see module docstring).

- Notion note-taking sub-agent (design §6e).
- Notion note-taking tool (design §8b).

  (design §3f). V2 will summarise old episodic entries and drop superseded

- Temporal range as a retriever filter — v1 only logs the extracted range
  for debug (design §4b); v2 will pass it as a `retriever.search` filter.
- Vector DB / hybrid retrieval (design V2 §1a, §2a).
- LLM-directed retrieval via a `search_memory` tool (design V2 §2b).
- Memory backups / snapshots (design V2 §1b).
- Mid-term memory tiers (`user_preferences/`, `project_context/`)
  (design V2 §1c).
- MCP integrations (Gmail, Calendar, Notion) and multi-step skills
  (design V2 §3a, §3b).

## 5. V1 simplifications vs. a "full" version

- **"Last session" temporal marker** (design §4b, query/preprocessor.py): treated
  as `(now − 24h, now)`. V2 will derive boundaries from stored session metadata.
- **Fallback retrieval** (design §4d): if compound keyword search returns 0
  results, retry with individual tokens (union of per-token hits). If still
  zero, return empty context — never fabricate.
- **`CURRENT_SESSION` intent** (manager.py): recognised but returns empty
  context in v1 — session-scoped search is unimplemented. Logged at DEBUG.
- **Metadata split** (typed_storage.py): `.md` files contain only content;
  metadata is managed exclusively by `JSONIndexer` (`index.json`). `load()`
  deliberately returns `metadata={}`; callers needing metadata query the
  indexer.
- **Strands owns conversation history** (design §5b, orchestrator.py): the
  design says "truncate conversation history oldest-first until it fits", but
  Strands manages its own history and does not expose mutation. V1 instead
  emits a critical alert (`alert: true`) when injected context nears
  `max_context_chars * 0.9`; operators must raise the budget or add
  summarisation.
- **Turn-level retry limit** (orchestrator.py, design §5f): design states "each
  turn allows at most one tool call"; v1 ships `DEFAULT_MAX_TOOL_CALLS = 10`
  and enforces the cap via a monkey-patched `validate_tool_use_name` in
  `main.py`. Tracked per-invocation in a `threading.local`.

## 6. Implementation decisions that extend or diverge from design.md

Items present in the shipped code but not spelled out in `design.md`, or that
implement the design with a different mechanism than the one described.

### 6.1 Dead-letter queue (new component, `src/memory/dlq.py`)
Not in `design.md`. Persistent JSONL-backed queue for failed `save_message`
writes, with a daemon background-retry thread controlled by a
`threading.Event` stop flag (`start_background_retry`). Entries exceeding
`dlq_max_attempts` are marked `dead=True` and left for manual inspection.
`retry_all` uses a load-outside / merge-inside pattern to avoid
self-deadlock when `save_message` enqueues during retry, and to preserve
entries added concurrently.

### 6.2 Typed markdown storage with O(1) manifest (`typed_storage.py`)
Implements design §3c but with a deeper episodic layout than the design
diagram (design shows `conversations/YYYY-MM/{session_id}.md`; implementation
writes `conversations/{session_id}/YYYY-MM-DD/{key}.md`). Every save goes
through a temp-file + `os.replace` to prevent partial writes, and the
manifest is rewritten atomically under a `threading.Lock`.

### 6.3 Dual-lock index concurrency (`indexer.py`)
`JSONIndexer` layers a `threading.Lock` (intra-process) on top of
`filelock.FileLock` (inter-process advisory lock on `{index_path}.lock`) so
concurrent sessions across threads *and* processes are safe. Writes still go
through temp-file + `os.replace` as a final safeguard.

### 6.4 Content-hash deduplication via indexer (`manager.py`, design §3e)
Implemented as `indexer.find_by_content_hash(sha256[:16])`; on a hit the
manager calls `indexer.touch(key)` to refresh the timestamp and skips the
write. Dedup is best-effort: an indexer error does not block the write.

### 6.5 Session-scoped isolation for shared infrastructure
- `MemoryManager._enforce_session_limit`: when `session_id` is set, only
  Redis keys whose `metadata.session_id` matches are counted and evicted, so
  concurrent sessions cannot evict each other's entries.
- `PostSessionHook._flush_redis`: filters by `metadata.session_id` before
  flushing so one session never flushes another's data.
- `create_memorize_tool(session_id=…)`: episodic entries are tagged with the
  active session so they land under `conversations/{session_id}/` rather
  than `unknown_session/`.

### 6.6 Prompt templating — Jinja2 instead of `string.Template`
Design §9d calls for Python string templates with `$variable` substitution
and "no Jinja2 dependency in v1". Implementation uses Jinja2 with
`StrictUndefined` (`src/prompts/loader.py`), and templates live as
`*.j2` files (`system_prompt.j2`, `context_prefix.j2`). The Jinja2
dependency is in `requirements.txt`.

### 6.7 Per-session log subfolders (`logging_config.py`, `main.py`)
Design §11a writes to flat `logs/app.jsonl`. Implementation creates
`logs/session_{session_id}_{YYYY-MM-DD}/` per session and routes loggers
to component files (`memory.jsonl`, `agent.jsonl`, plus the root
`app.jsonl`) via `LOG_COMPONENT_FILES`. Metrics write to
`metrics.jsonl` *inside* the session folder. Trace IDs are carried via a
`contextvars.ContextVar` so executor threads inherit the parent turn's
trace ID (explicit `copy_context()` in the orchestrator).

### 6.8 Log rotation in pre-session hook (design §11e)
`PreSessionHook._rotate_logs` deletes oldest entries until
`LOG_DIR_MAX_BYTES` (500 MB) is respected. Session subdirectories are
deleted as whole units to preserve per-session log integrity; legacy
root-level files are deleted individually for backward compatibility.

### 6.9 CoT/thinking-block stripping (`orchestrator.py`)
Reasoning/CoT models (DeepSeek-R1, QwQ, o1-style open weights) emit
`<think>…</think>` blocks via vLLM. Responses are run through
`_THINKING_TAG_RE` before being displayed or stored — raw chain-of-thought
never reaches the user or memory.

### 6.10 Strands issue #815 workaround (`main.py`)
`validate_tool_use_name` is monkey-patched at two binding sites
(`strands.tools.tools` and `strands.event_loop.streaming`) to:
1. Raise `InvalidToolUseNameException` instead of `TypeError` when a tool
   use arrives with `name=None` (happens with streamed tool calls from
   reasoning models); both callers already handle the exception cleanly.
2. Enforce the per-invocation `max_tool_calls` limit using
   `threading.local` so each agent call starts with a fresh counter.

### 6.11 LLM-ping classification (`pre_session.py`, design §7a)
`_check_llm` classifies SDK exceptions by class-name substring
(`Authentication` → `auth_error`, abort; `RateLimit` → `rate_limit`,
degrade). This keeps the hook portable across provider SDKs without a
hard dependency on any single exception type.

### 6.12 Graceful-error threshold in orchestrator (design §5c)
After `CONSECUTIVE_FAILURES_BEFORE_GRACEFUL = 2` consecutive turn failures
the loop resets the counter and displays the canned graceful-error message;
individual-turn failures show the raw exception. `tool_failures` increments
on every turn exception so the metric reflects orchestrator-visible
failures.

### 6.13 Session-lifecycle enforcement (`orchestrator.py`, design §5e)
Three exit paths cover the design's three conditions:
1. Explicit user command — any of `EXIT_COMMANDS` (`exit`, `quit`, `bye`,
   `/exit`, `/quit`).
2. `time.time() − _last_input_time > session_inactivity_timeout_seconds`.
3. `EOFError` or `KeyboardInterrupt` on stdin.
All three paths converge on `_close_session()` → `PostSessionHook`.

### 6.14 Post-session storage accounting
`_close_session` walks `memory_root` and the index directory with `os.walk`
and attaches `index_size_bytes` and `storage_size_bytes` to the metrics
dict before handing it to `PostSessionHook`. This satisfies design §11c's
"index size / storage size" without requiring the hook to know the paths.

### 6.15 Summary-turn selection under context budget (`post_session.py`)
`_select_turns_for_summary` iterates turns newest-first and includes each
one whose formatted text fits in the remaining `max_context_chars` budget;
oversized recent turns are skipped (so they don't block older, smaller
turns). Prevents the summary prompt from blowing the LLM's input budget
even on long sessions.

### 6.16 Tool-call timeout (`orchestrator.py`, design §5d)
Every agent call runs inside a `ThreadPoolExecutor(max_workers=1)` with
`future.result(timeout=tool_timeout_seconds)`. Timeout raises
`TimeoutError`, which is treated as a tool failure by the outer exception
handler and counted toward the consecutive-failure threshold.

### 6.17 Default LLM — local vLLM
`VLLM_BASE_URL`, `VLLM_MODEL_ID`, `VLLM_API_KEY` constants make a local
vLLM OpenAI-compatible server the default target; override via env/.env
for Claude or hosted OpenAI. Not prescribed in `design.md`; reflects the
local-development setup used throughout v1.

### 6.18 Rich-rendered console output (`orchestrator.py`)
Assistant responses render as Markdown via `rich.Console` +
`rich.Markdown` instead of plain `print()`. Strands' streaming printer is
disabled (`callback_handler=None`) so thinking blocks are stripped before
display.

## 7. Evaluation, tests, and metrics

Tracks design §10–§11 with minor layout deltas.

- **Golden dataset** (design §10b): `tests/golden/examples.json`.
- **Latency benchmarks** (design §10c): `tests/benchmarks/test_latency.py`
  with P50/P95 targets — memory retrieval < 100 ms, full turn overhead <
  200 ms (LLM excluded).
- **Structured JSON logs** (design §11a): every log line is a JSON
  object with `timestamp`, `level`, `trace_id`, `component`, `event`,
  `data`. Root logger catches uncategorised writes into
  `app.jsonl`; component loggers are split per `LOG_COMPONENT_FILES`.
- **Trace ID** (design §11b): UUID hex generated per user turn and
  propagated via `contextvars.ContextVar` across the agent executor
  thread.
- **Session metrics** (design §11c): extended with `duration_seconds`,
  `llm_token_count_est`, `llm_latency_ms`, `tool_calls_made`,
  `tool_failures`, `eviction_count`, `index_size_bytes`,
  `storage_size_bytes`. Written once per session to
  `session_*/metrics.jsonl`.
- **Critical alerts** (design §11d): emitted at `ERROR` with
  `alert: true` by: memory-root not writable, Redis unavailable at
  session start, LLM context near 90% limit, DLQ entry marked dead.

## 8. Follow-up / open issues for V1.1

- V1 does not activate the retained `MemorizeSubAgent` — auto-memory
  (post-turn) is the planned hook to wire it in.
- Design §5b truncation is still an alert-only signal because Strands
  controls history; an explicit compaction pass is needed to enforce the
  budget.
- Temporal extraction is logged but not used as a retriever filter.
- A `MemoryProvider` protocol is staged on branch `v1.1`
  (`src/memory/provider.py` + ReMeLight adapter) to let the orchestrator
  swap memory backends without touching call sites.
